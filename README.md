# Harness 从入门到落地

## 序言

如果你正在阅读这份资料，大概率你已经感受到了 AI 编程的那种**矛盾**：

它能帮你写代码，但写出来的效果总在某些方面不尽如人意；
它能理解需求，但聊着聊着常会偏离预设的轨迹；
初接触时感觉他像魔法，但随着使深入使用会觉得他越来越像玄学。

这种矛盾不是 AI 不够强——它源于一个根本问题：**我们还在用"对话"的方式驾驭一个本应工程化的能力**。

**Harness Engineering** 就是对这个问题的系统性回答。它不是某个工具或框架，而是一种**工程范式**——通过结构化文档、阶段化流程、原子化任务，把不可控的 AI 编码改造为可重复、可审计、可演进的工程过程。

---

## 这套资料想做什么

业界关于 Harness 的资料散落各处：官方文档，各路博客，论文。但很少有资料把"是什么"-"为什么"-"怎么用"串成一条完整路径：你看完 Spec-Kit 的教程，感觉很棒，但不知道它适不适合你；试用了 GSD，感觉有点重，但不知道哪些可以裁剪；想自己设计工作流，又担心效果不符合预期，无从下手。

这套资料想解决的就是这种**知道但不通透**的状态——它不是教你"怎么用 OpenSpec"——这种知识在官方文档里更准确。它的目的是帮助你**深入理解 Harness 框架和背后的设计哲学**；让你在**面对任何项目场景时，都能做出明智的取舍。**

通读后你应该能：

- 拆解任意 Harness 框架的设计——它在三大原理上做了什么权衡
- 评估任意框架对你项目的适配度，并预判会出现哪些摩擦
- 不论是复用还是自研，能够将 Harness 框架完整应用到你的项目中，助力生产

---

## 应该怎么读

整套资料分三层：**理论认知**（10 篇）→ **决策评估**（1 篇）→ **执行落地**（2 篇，二选一）。

建议从 **文档 0（入门导论）** 开始，它的后半部分有完整的学习路径推荐。如果时间紧张，至少完整读完文档 0、文档 1（知识图谱）、文档 10（试用评估）——这三篇构成了最小可用的认知闭环。

---

## 几点提醒

**不用追求"读完"**——全文分为理论篇、框架、实战，请根据你现有对 Harness 的理解选择性的精读，对于想更深入了解的部分，可以看看每章结尾的延伸阅读和参考资料。

**没有银弹**——每个框架都有他的优势和局限。**学习的目的是让你能正确理解和批判，而不是崇拜它们。**

**干中学**——理解了 Harness 原理不代表你会设计 Harness，**真正的掌握来自在自己项目中逐步踩坑**。

**知其所以然**——Harness 自 2025 年兴起后不断在剧烈演进。各类实践层出不穷，但其**核心原理**始终是稳定的，理解现实工程中的问题和解决思路，才是学习的最终目的。

## 写在最后

如果你看完觉得"现有框架我都不想用，我想自己设计一套"——那是**工程师独立思考的成熟**。
如果你看完觉得"OpenSpec 就够用了，先用着再说"——那是**工程师复用为先的克制**。

这套资料不灌输结果，只想让你**有能力为自己的项目找到答案**。

愿你读完后，下次和 AI 协作时，眼里多一份清明。

希望本文能帮助到更多同学，让我们共同跋涉在开悟之坡上。
